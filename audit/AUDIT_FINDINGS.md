### injector
_The injector (injector/src/main.cpp) is a clean, well-commented single-file remote-LoadLibraryW tool with good error handling and a recently-hardened wide-char/path layer. - [bug/medium] `injector/src/main.cpp:179-189` — Success is determined by `GetExitCodeThread(remote_thread,&exit_code); return exit_code != 0;`. The remote thread runs LoadLibraryW, whose return value is an HMODULE (a 64-bit pointer on x64). The thread exit code is a 32-bit DWORD, so it captures only the LOW 32 bits of the returned HMODULE. If the DLL's base address has zero low-32-bits (possible under high-entropy ASLR, esp. for a relocated module), a SUCCESSFUL load reports exit_code==0 → injector falsely prints 'Injection failed' and returns EXIT_FAILURE. Conversely any non-zero low word reads as success even if the DLL's DllMain later partially fails. This is the well-known limitation of the exit-code-as-result pattern. → Treat WaitForSingleObject completion as 'thread ran'; do not use the truncated exit code as the load-success oracle on 64-bit. Either (a) verify the module is present via CreateToolhelp32Snapshot(TH32CS_SNAPMODULE) on the target after the thread returns, or (b) document that exit_code is only a coarse signal and a 0 result is inconclusive rather than a hard failure. At minimum add a comment noting the 32-bit truncation.
